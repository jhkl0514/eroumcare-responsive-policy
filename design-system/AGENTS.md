# design-system/AGENTS.md — DS 문서 페이지 작업 지침

`design-system/` 안에서 일할 때 이 문서를 따른다. 저장소 루트 `AGENTS.md`(수정 범위 · 브랜치 · 커밋 규칙)가 먼저 적용된다.

## 1. 견본

아래 페이지가 승인된 기준이다. 새 페이지는 이 중 가장 비슷한 것을 복사해서 시작한다. 구조 · 문장 길이 · 간격을 따라 한다.

| 종류 | 견본 |
|---|---|
| 입력 컴포넌트 | `viewer/text-input.html` · `viewer/select.html` (손으로 쓴 페이지) · `viewer/src/textarea.html` |
| 동작 컴포넌트 | `viewer/src/button.html` · `viewer/src/modal.html` |
| 상태 표시 | `viewer/src/status-chip.html` |
| 파운데이션 | `viewer/src/color.html` · `typography.html` · `shape.html` · `layout.html` · `icon.html` |

## 2. 작업 순서 (빠뜨리지 않는다)

1. **값 읽기** — DS Figma `64Q1Re56aiAA8Al89pqjnV`에서 해당 컴포넌트 노드를 직접 연다. 크기 · 색 · 글자 · 여백을 노드에서 읽는다.
   - Figma에 접근할 수 없으면 값을 지어내지 않는다. 그 값은 "확인 필요"로 표시하고 보고한다.
   - 정책 허브 `CLAUDE.md` 3장과 다르면 정책을 따르고, 다른 점을 보고한다.
2. **CSS** — `css/components.css`에 추가한다. 색 · 간격 · 모서리는 `css/tokens.css` 변수만 쓴다(값 직접 쓰기 금지).
3. **페이지** — `viewer/src/<이름>.html`을 쓴다(블록: `@title` `@crumb` `@lead` `@meta` `@design` `@dev` `@after` `@script`).
4. **조립** — `python3 design-system/tools/build-viewer.py`
5. **메뉴 연결** — `viewer/doc.js`의 `PAGES`와 `viewer/index.html`의 `NEW`에 같은 이름으로 추가한다. 추가하지 않은 항목은 `item.html`이 같은 틀 안에서 기존 문서나 "준비 중"으로 보여 준다.
6. **점검** — `python3 design-system/tools/check-viewer.py <이름>.html` → ✗가 하나도 없어야 한다.
7. **눈으로 확인** — `viewer/_review/<이름>-360.png` · `-1440.png`를 **직접 열어 본다**. 점검 스크립트가 못 잡는 것(겹침, 어색한 줄바꿈, 빈 곳, 정렬)을 여기서 찾는다.
8. **보고** — 아래 6번 양식으로.

토큰을 바꿀 때는 `tokens/figma-variables.json`을 고치고 `node design-system/tools/build-tokens.js`를 실행한다. `css/tokens.css`를 손으로 고치지 않는다.

## 3. 페이지 구조

- **디자인 탭** (디자이너가 읽는다): 개요 → 구조 → 상태 → 크기와 간격 → 사용 예 → 사용 원칙
- **개발 탭** (개발자 · AI가 읽는다): 기본 마크업 → 클래스 → 상태 만들기 → AI 코딩용 요약
- 맨 위: 이름 · 한 줄 설명 · Figma 링크 칩. 오른쪽 목차, "← 정책 허브" 링크는 공통 틀에 이미 있다.

## 4. 규칙 체크리스트

**글**
- 글자 크기는 본문 16 · h1 32 · h2 24 · h3 18이다. 새 크기를 만들지 않는다.
- 문장은 짧게, 존댓말 "~합니다"로 쓴다. 설명은 "무엇을 · 언제"만 쓴다.
- 디자인 탭에는 클래스명 · 토큰 이름 · 코드를 쓰지 않는다. 색은 `#323DA3`처럼 값으로 쓴다.
- 정책 근거는 조항 칩으로 단다(예: `3-4`).

**보이는 것**
- 예시는 그림이 아니라 실제로 동작하는 컴포넌트를 쓴다. 누르고 입력할 수 있어야 한다.
- 사용 원칙은 "이렇게 / 이렇게 하지 않기" 실물 비교 카드로 만든다. 글만 있는 카드는 쓰지 않는다.
- 번호 원(①②)은 구조 섹션에서만 쓴다.
- 치수선은 꼭 필요한 곳에만 쓴다. 숫자는 손으로 적지 않고 화면에서 잰다(`data-dims`).
- 간격은 8의 배수로 맞춘다.
- 장식은 하지 않는다. 카드 위 색 띠, 그라데이션, 이모지, 그림자 남용이 해당된다.
- 360px에서 가로 스크롤이 없어야 한다. 넓은 표는 `.doc-scroll`로 감싼다.

**코드**
- 코드 복사 버튼은 개발 탭에만 둔다.
- 한 페이지 안에서 `id`가 겹치면 안 된다(겹치면 스크립트가 엉뚱한 요소를 잡는다).
- 예시 데이터는 가짜 값만 쓴다. 이름은 "홍길동", 번호는 `010-0000-0000`, 주소는 "101동 1001호" 같은 값이다.
- 내부 프레임워크 사이트 주소는 저장소에 쓰지 않는다.

## 5. 하지 말 것

- 견본에 없는 새 레이아웃 · 새 장치(접히는 카드, 탭 안의 탭 등)를 만들지 않는다. 필요하면 먼저 묻는다.
- Figma와 다른 값을 "더 나아 보여서" 쓰지 않는다. 다르게 하고 싶으면 제안으로 보고한다.
- 다른 컴포넌트의 CSS를 함께 고치지 않는다. 고쳐야 하면 보고한다.
- 점검(6번)과 눈 확인(7번)을 건너뛰고 "완료"라고 보고하지 않는다.
