# 이로움케어 반응형 디자인시스템

`CLAUDE.md`(이로움케어 반응형 정책 통합 문서)를 화면 제작/검수 작업에 바로 쓸 수 있게 패키징한 스킬입니다. 이 스킬은 **규칙 요약본**이며, 최신 원본과 화면별 결정 이력(왜 이 값인지, 언제 확정됐는지)은 항상 `CLAUDE.md`를 우선합니다. 이 프로젝트 밖(실제 개발 리포)에서 쓸 때는 아래 규칙만으로도 충분히 동작하도록 자기완결적으로 작성했습니다.

## 1. 브레이크포인트 (최우선 — 모든 컴포넌트가 이 값을 인용)

- **1024px** — PC ↔ 모바일 전환 기준. 전역 유일한 1차 분기. **1024px 이하 = 모바일, 1025px 이상 = PC**(정확히 1024px·아이패드 가로도 모바일). CSS: 모바일 `max-width:1024px`, PC `min-width:1024.02px`
- **앱별 사이드바 숨김(PC 구간 내 2차 기준)**: 이로움케어 사업소 **1199px 이하** SNB 숨김 / 대대여(창고·설치파트너) **1439px 이하** SideNav 숨김 → 햄버거로 콘텐츠 위 오버레이, 콘텐츠·GNB 최소 폭 1440 유지 + 가로 스크롤. 모바일은 두 앱 모두 1024px 이하. 대대여 모바일(현재 별도 React)은 사업소처럼 PC 화면 안 1024px 전환으로 변경 대상
- **360px** — 모바일 구간 내 하위 기준(모바일 최소 지원폭, 모달 Full 전환).
- **폐기된 값(쓰지 말 것)**: 480px, 640px, 768px, 1060px.
- **1060px는 브레이크포인트가 아니라 PC 콘텐츠 영역 고정 폭**이다 (contents_wrapper). 전 PC 화면 공통, 페이지마다 다르지 않음. 정해두지 않으면 초광폭 모니터에서 콘텐츠가 무한정 늘어난다.
- 1024px은 레이아웃 기준이지 입력장치 기준이 아니다 — 터치 노트북/랜드스케이프 태블릿도 1025 이상이면 PC 레이아웃. 단 hover 전용 인터랙션은 만들지 않고 클릭으로도 100% 동작하게 만든다.

## 2. 반응형 vs 적응형 — 화면 만들기 전에 먼저 판단

| 구분 | 정의 | 적용 |
|---|---|---|
| 반응형 | 같은 DOM을 CSS로 재배치, 화면 하나로 전 구간 대응 | 상세보기, 모달 |
| 적응형 | PC/모바일이 구조 자체가 다름(테이블 vs 카드), 두 구조 다 준비 후 표시만 전환 | 리스트 |

판단 기준: 정보 밀도·인터랙션 패턴이 PC/모바일에서 본질적으로 다르면 적응형, 배치만 바꿔도 되면 반응형.

## 3. 컴포넌트별 반응형 규칙

### 3-1. 텍스트형 (읽기전용 정보 테이블)
label-value 나열형 데이터(주문 정보, 회수 신청 정보 등).
- 라벨 셀: `max-width:128px; min-width:80px`, 배경 `#f5f5f5`
- 값 셀: `min-width:160px`
- **flex-shrink만 사용, wrap 없음** — 최소 240px(80+160)까지 좌우 2열 유지, 별도 스택 폴백 불필요
- 배경 없는 variant(예: 회수정보 조회형)는 라벨 125px, 배경 없음

### 3-2. 입력필드형 (실제 입력 가능한 폼 필드)
배송정보 수정, 회수지 주소 수정 등.
- 라벨: **125px 고정, `flex-shrink:0`**
- 콘텐츠: `flex:1 0 0`, 최소폭은 모드에 따라 다름
  - 수정 모드: `min-width:280px` → 줄바꿈 전환점 = 125+gap(4)+280 = **409px**
  - 조회 모드: `min-width:180px` → 전환점 = 125+gap(8)+180 = **313px**
- 이 전환점은 브레이크포인트로 못박은 값이 아니라 공식에서 나오는 결과 — 라벨 폭/최소폭이 바뀌면 전환점도 바뀐다. **문서에는 숫자가 아니라 공식을 남길 것.**
- flex-wrap 컨테이너라 미디어쿼리 없이 순수 flexbox로 동작
- PC(1025px 이상) 상한: 입력 콘텐츠 영역은 `max-width:480px`에서 멈춤

### 3-3. 모달
**타입 판단 기준은 테이블(행/열 데이터) 포함 여부 — 요소 개수가 아님.**

| 유형 | 사이즈 |
|---|---|
| 텍스트형(안내/확인) | sm-340 |
| 정보확인/입력형/검색-리스트형 | md-480 |
| 테이블 포함형 | lg-600 / xl-800 |

반응형 규칙:
| 구간 | sm-340 | md-480 | lg-600/xl-800 |
|---|---|---|---|
| 1025px↑ | 340 고정 | 480 고정 | 600/800 고정 |
| 360~1024px | 340 고정 | 340으로 축소 | Full(테이블 가로 스크롤) |
| 360px 미만 | Full, 좌우 마진 10px | 〃 | 〃 |

- md/lg 모달이 1025px 이상일 때 버튼은 전체폭 분할 대신 **각 150px 고정폭 + gap 12px, 가운데 정렬**. sm-340은 항상 전체폭 분할.
- 정중앙 정렬, 오버레이는 하나만(새로 열리면 기존 것 자동 닫힘), 내용 넘치면 모달 자체 `max-height` + 내부 스크롤.

### 3-4. 액션 버튼 배치
- **PC**: 페이지 타이틀 옆(우측), Hug 사이즈(`flex:0 0 auto`) — 전체폭 분할 금지
- **모바일**: 타이틀 아래로 이동 + 화면 하단 sticky 플로팅(흰색 그라데이션 페이드), 버튼은 폭을 나눠 가짐(Full)
- 모바일 하단 sticky는 `env(safe-area-inset-bottom)` 필수

### 3-5. 팝오버 / 바텀시트
- **PC**: anchored popover, 호버 200ms 지연 후 열림 / 300ms 지연 후 닫힘. 다른 그룹 아이콘 호버 시 기존 팝오버 즉시 닫고 새로 열림
- **모바일**: 탭하면 바텀시트
- 달력/셀렉트 드롭다운도 동일 원칙: 모바일은 트리거와 동일한 좌우 여백(`left:0;right:0`), PC만 고정폭
- 바텀시트 공통: 상단 모서리 반경 **40px**, 드래그 핸들바 없음(타이틀+X로 바로 시작), 타이틀 상단 여백 **32px**(바깥 래퍼 12px + 안쪽 Contents 래퍼 20px 합산 — 이중 래퍼 구조 그대로 가져갈 것, 단일 패딩 아님)

### 3-6. 페이지네이션 (PC 전용, 모바일엔 이 컴포넌트 자체가 없음)
- 3분할(`justify-content:space-between`): 좌측 "전체 N/M" 건수 · 중앙 이전/다음+페이지번호 · 우측 "N개씩" 크기선택
- 페이지 번호 버튼: **32×32px, radius 4px** — 원형/알약 아님
- 활성 페이지: 브랜드색 꽉 채움 아님, **연한 틴트 배경 `#eff1fd` + 진한 텍스트 `#141e76` semibold**
- 이전/다음: 테두리 없는 아이콘 버튼(24px 아이콘, 32×32 히트 영역), 비활성 시 투명도로만 표시
- 모바일: 카드 리스트 + 별도 스크롤/더보기 방식 (페이지네이션 대체 아님, 완전히 다른 패턴)

### 3-7. 검색 영역 (리스트 화면 전용 — 적응형)
- 검색은 리스트에만 있으므로 **적응형**: PC 패널 / 모바일 칩+시트를 둘 다 두고 1024/1025px 경계에서 표시만 전환. 상세는 반응형
- **PC 패널**: bg `#fafafa`, 테두리 `#bdbdbd`, radius 4, 패딩 16 / 행 높이 44 + 구분선 `#eee`, 2열 / 라벨 **120px** 14px SemiBold / 첫 행 **날짜**: 기준 셀렉트 160 + 시작일~종료일 각 160(달력 아이콘, yyyy-mm-dd) + 세그먼트 오늘/어제/일주일/지난달/3개월(칸 68×32, 선택 bg `#e0e0e0`) / **체크박스 복수 선택**(20×20, 선택 `#323da3`), 기본은 "전체"만 체크 → "전체" 누르면 같은 행 모두 체크(기획 합의) / 셀렉트·달력은 **DS 컴포넌트**(옵션 패널, `calendar_Default` 팝오버 — 선택 `#90ee02`, 호버 `#f2fde4`), 네이티브 select·date 금지 / 검색어 셀렉트(전체/바코드/상품명/사업소명) 160×40 + 입력 264×40 / 하단 초기화(아웃라인)·검색(필드) 각 130×36 / 우상단 "접기"(bg `#eee`, ▲) — **기본 펼침**, 접으면 날짜 행+버튼만 남고 라벨 **"상세"**
- **모바일**: ① 필터칩 줄(56px, 가로 스크롤, 칩 표기는 **기본 "이름 : 값" / 선택 시 값만**, 선택 시 bg `#f5f5f5`+테두리 `#999`+SemiBold, 우측 "검색" 칩 고정) ② 적용 태그 줄(48px, 조건 있을 때만, **`#09af00`** 글씨+X, 우측 "초기화") ③ 건수(56px)
- 칩 탭 → 단일 선택 시트(선택 행 틴트 `#eff1fd`+체크, "선택완료") / "검색" 칩 탭 → 검색 시트(버튼 그리드 4개=2열·3개=3열, 선택 테두리 `#333`, 하단 초기화 120px + 검색)
- **모바일은 모든 필터 단일 선택** — PC 복수 선택과 다름
- 모바일 날짜: 일주일/이번달/3개월/**직접선택** + 시작일~종료일(직접선택일 때만 활성) → 누르면 검색 시트 대신 DS 달력 바텀시트, "선택완료"로 복귀

### 3-8. 모바일 간격 (디자인시스템 "모바일 정의")
- 카드 UI 패딩: 기본 `24/16`, 상단에 상태값이 붙는 카드 `16 16 24 16`
- 카드 리스트: 카드 사이 12px, 건수 영역 있으면 건수–첫 카드 0 / 없으면 20px
- View(상세) 화면 컨테이너: `24/20`, gap 4(아코디언 `8/20`) / 입력 화면 컨테이너: `24/20`, gap 24
- 화면 좌우 여백 20px
- 바텀시트 높이: 고정 px 없음(디바이스 높이마다 다름) — 시트 최대 높이는 화면 비율, 넘치면 콘텐츠만 스크롤
- 모바일 홈 버튼: 3depth부터 노출(입력 페이지, 액션 후 다음 depth는 예외)
- 건수 영역 우측에 정렬 셀렉트 노출/비노출 가능

### 3-9. 리스트 본문 — PC 테이블 ↔ 모바일 카드 (적응형)
- PC: 밑줄 탭 + 우측 일괄 처리 버튼(체크한 행 대상) / 헤더 52 `#f5f5f5`, 행 52 구분선 `#eee` / 체크박스 44(헤더=전체 선택), 선택 행 `#eff1fd` / 날짜 컬럼 정렬(기본→오름→내림)
- 컬럼 합이 콘텐츠 폭 초과 시 좌측 식별 컬럼(체크박스+바코드+상품명 = 440px) 고정 + 나머지 가로 스크롤, 표 아래 "표를 밀어보세요." 힌트 / 아래 페이지네이션(3-6)
- 모바일: 풀폭 탭 → 검색 → 건수 → 카드(3줄: 상태 배지+품목+모델 / 바코드 Bold / 보조 정보 1줄, 패딩 24/16, radius 8)
- 모바일엔 체크박스·일괄 처리 없음 — 카드 누르면 상세 화면(누른 카드 bg `#eff1fd` + 테두리 `#141e76`). 페이지네이션 없음

### 3-10. 카드 목록형 (PC·모바일 모두 카드 — 반응형)
- 기준: 운영 디자인 "260824_수급자관리 목록 필터" To-Be(수급자 통합관리 목록). 정책은 디자인 기준 — 퍼블은 대조용
- 한 건의 정보·행동이 많으면 PC도 카드, 같은 카드를 폭에 따라 재배치(3-9 테이블↔카드와 다른 유형)
- 상세 조건 패널 기본 접힘 + 슬라이드, 적용 조건은 필터 태그(bg `#eff6ff`, 테두리 `#dbeafe`, 글자 `#1e40af`, X로 개별 해제 + 즉시 재조회)
- 카드: 테두리 `#bdbdbd` r4, 사이 8, 헤더 `#fafafa`(이름 + 상태 배지 인라인), 모바일은 정보 한 줄씩 → 대여종료 박스 → 메모 아래로, 주 버튼 전체폭
- 입력·버튼: PC 36~40 / 14px → 모바일 48 / 16px. 모바일에도 페이지네이션(3-6 예외)

### 3-11. 상세 화면 공통 요소
- 정보 표 PC 2쌍/행(라벨 배경) → 모바일 1쌍/행 / 아코디언 섹션(헤더 배경 구분, 제목 좌우 패딩 0) / 모바일 첨부 썸네일 100px 가로 스크롤
- 목록 돌아가기: PC 맨 아래 오른쪽 버튼, 모바일 상단 뒤로가기 / 모바일 뒤로가기 터치 48×48, tel 링크, 하단 고정 LG 54 + 흰색 그라데이션, 키보드가 입력칸 가리지 않게

## 5. 코드 레벨 원칙 (반복 발생한 실수에서 도출 — 새 화면 만들 때 기본 적용)

1. **모든 input/select/커스텀 필드는 배경·글자색을 명시적으로 지정한다.** 미지정 시 OS 다크모드에 따라 브라우저가 임의 렌더링(실제 버그: select 검은 배경).
2. **아이콘은 이모지가 아니라 인라인 SVG.** 텍스트 화살표(▾▲▼)나 `☰`/`✕` 같은 기호도 SVG로. `<select>` 기본 화살표도 `appearance:none`+`background-image`로 커스텀 SVG 지정(우측 인셋은 보통 12px, 다른 입력요소 좌측 패딩과 대칭).
3. **하단 고정 요소는 `env(safe-area-inset-bottom)` 필수.**
4. **오버레이는 항상 하나만** — 새로 열리면 기존 것 먼저 닫기.
5. **레이어 hidden 상태를 상태 전환마다 정확히 관리.** 화면 복제 시 hidden 재검토 필수(정상 버튼이 hidden 처리되고 범용 버튼만 노출되는 사고가 반복 발견됨).
6. **폰트는 SUIT, 사이즈는 14px 이상 짝수(14/16/18/20/22...)만.** SUIT는 `https://cdn.jsdelivr.net/gh/sunn-us/SUIT@2/fonts/static/woff2/SUIT.css`로 로드, `font-family` 최우선 지정. 예외: Figma가 명시적으로 작은 값을 지정한 배지류(예: 원형 숫자 배지 9px)만 유지 가능 — 임의로 홀수/13px 이하로 조정 금지.

## 6. 화면 제작/검수 워크플로우 (Figma MCP 활용 시 — 반드시 지킬 것)

**숫자를 추측하지 말고 항상 Figma에서 실측한다.** 라벨 폭·gap·min-width 같은 값은 감으로 쓰지 말고 `get_metadata`(구조 파악) → `get_design_context`(실제 스타일/컴포넌트 바인딩)로 직접 확인한다.

**컴포넌트 variant 개수를 판단할 때 반드시 마스터 컴포넌트를 확인한다.** `get_design_context`는 **그 화면에 실제로 쓰인 variant만** property 타입에 나열한다 — "이 화면에 6개 상태만 보인다"를 "컴포넌트에 6개 variant만 있다"로 오판하지 말 것. 실제로 이 프로젝트에서 이 실수를 한 적이 있다(Status chip-Rental이 9개 variant를 전부 갖고 있었는데, 화면에 6개만 쓰여서 "3개가 없다"고 잘못 진단함). 컴포넌트의 진짜 전체 variant 목록을 보려면:
- `search_design_system`(entity: "component")으로 컴포넌트 검색 후 라이브러리 파일에서 마스터 컴포넌트 노드를 직접 `get_metadata`로 열어 모든 `Property 1=...` symbol을 확인, 또는
- 디자인시스템 캔버스(컴포넌트 모음 페이지)에서 같은 이름의 컴포넌트 프레임을 찾아 대조

**인스턴스인지 raw 도형인지 구분한다.** `get_design_context` 결과가 `<ComponentName property1="..." />` 형태로 함수 호출처럼 추상화되면 진짜 컴포넌트 인스턴스, 매번 인라인으로 markup이 풀어써지면 raw 도형(컴포넌트 아님)일 가능성이 높다. 같은 컬럼/영역 안에서 어떤 셀은 인스턴스, 어떤 셀은 raw로 섞여 있으면 디자인시스템 검수에서 반드시 지적할 것 — 색상이 우연히 같아도 유지보수 시 갱신이 안 되는 문제로 이어진다.

**같은 라벨이라도 도메인이 다르면 다른 컴포넌트다.** 예: "배송완료"가 `Status chip-Order`(구매)와 `Status chip-Rental`(대여) 양쪽에 있을 수 있다 — 화면의 실제 도메인에 맞는 컴포넌트를 쓰고 있는지 확인.

**새 프로토타입/화면 파일을 만들 때는 기존 harness 패턴을 그대로 따른다**(이 리포 기준, 다른 코드베이스에서도 참고):
- SUIT 폰트 `<link>` + `font-family` 최우선 지정
- `@container pf (max-width:1024px)` / `(min-width:1024.02px)` 형태로 1024/1025px 경계 분기 (미디어쿼리 아닌 컨테이너쿼리)
- 프리셋 폭 버튼(320/360/1024/1025/1440)으로 브레이크포인트 구간을 클릭 한 번에 확인 가능하게
- PC 콘텐츠 영역은 `max-width:1060px`로 캡핑
- 적응형(리스트) 화면은 `.pc-view`/`.mo-view` 같은 명시적 분기, 반응형(상세/모달) 화면은 단일 DOM 유지
